# Git 历史与提交详情交互设计

日期：2026-10-31。

状态：核心交互已实现，验收见 [Git 历史交互验证](../verification/git-history-interaction.md)。用户已明确独立 Commits 区块可以去掉；以提供的 VS Code 侧栏图表、独立 Git Graph 标签和工具栏大图入口为交互参考。保留两种展示，沿用 HerdrWork 的 Ratatui、Crossterm、终端字体和现有主题。

## 改动前的行为

- `Graph` 使用所有引用的提交拓扑；`Commits` 使用当前 HEAD 可达的提交列表。两者范围不同，但都承担提交历史导航，作为并列入口容易混淆。
- 来源侧栏同时提供两个入口；根 TUI 的侧栏已经隐藏 Graph，并在内容区提供 Graph 标签。实施时需统一两条呈现路径：侧栏保留内嵌 Graph，移除 Commits，工具栏提供独立大图入口。
- 现有 Graph viewer 支持双击提交查看详情，Enter 打开顶部提交，Backspace 返回。单击没有提交详情联动，也没有提交下的变更文件树。
- 文件历史有独立的文件范围，仍有保留价值。

依据：[Git 查询](../../crates/herdr-work-code/src/git.rs)、[来源侧栏](../../crates/herdr-work-code/src/scm_app.rs)、[viewer 导航](../../crates/herdr-work-code/src/viewer.rs)、[根 TUI 侧栏](../../crates/herdr-work-tui/src/sidebar_view.rs)、[既有 Graph 验证记录](../verification/git-graph.md)。

## 信息结构与两种展示

Git 侧栏按“Changes → Graph → File History → 仓库资源”组织，移除独立 Commits 区块。Graph 直接展示可选择的历史行，不再只是打开另一个列表的按钮。

| 展示 | 入口 | 主要用途 |
| --- | --- | --- |
| 侧栏内嵌 Graph | Git 侧栏的 Graph 区块 | 快速选择提交，在提交行下展开文件，单击文件查看 Diff |
| 独立完整 Git Graph | Git 工具栏的图谱按钮，提示“打开 Git Graph” | 在独立标签中查看完整拓扑、引用和提交信息 |

工具栏按钮是打开大图的操作，不占用一个可展开的侧栏区块。点击后打开或聚焦当前 worktree 的 Git Graph 标签，重复点击不重复创建。根 TUI 现有 Graph 内容标签复用为这一完整视图，不再增加第三种同义视图。关闭大图不会关闭侧栏 Graph，也不清除其展开状态。

两种视图都提供“全部引用 / 当前分支”范围选择，默认“全部引用”，以便继续访问未合并分支的提交；切换到当前分支覆盖原 Commits 的主要用途。范围切换仅影响查询，不切换 Git 分支。两种视图分别保留筛选、滚动和选中状态，打开已有大图不会重置其位置。

File History 标题保留当前文件名，明确是某个文件的提交记录，继续使用原有文件范围查询和历史导航。

## 侧栏布局

采用 VS Code 的提交行下展开文件结构，详情复用右侧内容区。默认同时展开一个提交；切换提交收起上一项，避免文件列表挤占整个历史。

```text
Git                 [打开大图]   │ Commit · a1b2c3d4                 [固定]
Changes                       0  │ fix(diff): 切换文件时定位第一处差异
                                 │ 作者：示例作者   日期：2026-10-31 10:30 +08:00
▾ Graph       [全部引用 ▾] [刷新] │ SHA：a1b2c3d4…                    [复制]
│                                │ 父提交：b2c3d4e5
● ▾ fix(diff): 切换文件… [main]   │
│    M CHANGELOG.md               │ 完整提交说明正文……
│    M viewer.rs                  │
│      crates/herdr-work-code/src │ 5 个文件  +42 −12
│    M changes.rs                │
● ▸ feat(ui): 支持全文对照…       │ M CHANGELOG.md                    +3 −0
● ▸ feat(ui): 适配 macOS…         │ M crates/…/viewer.rs             +22 −8
│                                │ …
▸ File History · viewer.rs       │
▸ Branches                       │
▸ Worktrees                      │
```

以上提交号、身份、时间与统计均为示例。终端宽度不足时，提交行优先保留拓扑、展开标记和说明；分支标签限制宽度，作者与日期放入详情。文件行优先显示状态和文件名，目录作为次级文字；重名文件必须显示可区分的目录。

## 独立大图布局

完整 Git Graph 在内容区独立标签展示，保留现有拓扑、引用、说明、日期、作者及 SHA 列，不在每个提交下插入文件行。

```text
[Git Graph ×]                           [全部引用 ▾] [刷新]
Graph  提交说明                         日期       作者  SHA
●      [main] fix(diff): 切换文件…       2026-10-31 示例  a1b2c3d4
│ ●    [feature] feat(ui): …             2026-10-30 示例  b2c3d4e5
├─╯
●      feat(ui): 支持全文对照…           2026-10-29 示例  c3d4e5f6
─────────────────────────────────────────────────────────
提交详情 · a1b2c3d4                              [收起详情]
完整说明、作者、时间、父提交、文件统计
M CHANGELOG.md                          +3 −0
M crates/…/viewer.rs                    +22 −8
```

单击大图提交在标签下方显示详情，保留上方拓扑，便于连续切换提交；点击文件在大图标签内临时查看历史 Diff，返回后恢复大图选择和滚动位置，标签保留 Git Graph 身份。高度不足时详情占用当前内容区，提供显式返回图谱入口。两种布局复用同一提交详情和 Diff 能力。

## 侧栏鼠标与键盘

| 操作 | 结果 |
| --- | --- |
| 单击提交行 | 选中提交、展开变更文件，右侧显示该提交详情；再次点击仍保持选中 |
| 单击提交前的展开标记 | 只展开或收起文件，保留当前右侧内容 |
| 单击提交下的文件 | 右侧显示该提交中该文件相对所选父提交的 Diff |
| 单击详情中的文件 | 打开同一文件 Diff，与侧栏行为一致 |
| 双击提交或文件 | 固定相应详情或 Diff 标签，不重复创建同一目标 |
| 上下键 | 在侧栏可见提交、文件行间移动，保持焦点；Enter 执行该行的单击动作 |
| 左右键 | 收起或展开；文件行按左键返回所属提交行 |
| Tab | 按现有工作台约定在侧栏与内容区切换焦点 |
| Backspace 或可点击的返回入口 | 文件 Diff 返回所属提交详情；独立完整历史页的详情返回原历史位置 |

单击预览保持侧栏焦点，方便连续选择；点击右侧内容才转移焦点。工作区已经有固定标签时，历史预览按既有临时标签规则打开。每次选择更新临时预览，双击或“固定”后保留该目标。

## 提交详情与文件 Diff

提交详情显示完整标题、正文、作者、带时区的提交时间、可复制的完整 SHA、父提交、直接指向该提交的分支与标签、变更文件数及增删统计。作者与提交者不同时同时展示两者；长正文可滚动，不截成一行。

文件 Diff 顶部显示“Graph › 短 SHA › 文件”，提供返回提交入口，并复用现有 Diff 呈现、全文对照、差异导航、查找与复制。切换历史文件时定位第一处差异；重复选择相同文件保留阅读位置。

比较目标始终是选中的提交与其父提交，不混入工作区未提交修改。重命名显示旧路径到新路径；删除文件保留删除前内容；二进制文件显示类型与变更提示。新增提交没有父提交时与空树比较。

合并提交默认比较第一父提交，详情与 Diff 顶部明确显示比较基准，并可选择其他父提交。文件列表、统计和 Diff 随同一个基准更新，避免显示不一致。

## 终端与状态边界

- 侧栏采用纵向列表，提交与文件使用既有内容预览布局；独立大图仅在选中提交时展示下方详情，不增加常驻横向分屏。窄窗口保持相同导航层级。
- 首次展开显示归属该提交的“正在加载变更文件…”；失败在原位置显示错误和重试。加载结果不能抢走焦点或把列表跳回顶部。
- 快速选择 A、B 或切换仓库后，旧请求不能覆盖新选择；以 worktree 身份、完整提交 OID、父提交及文件路径标识目标，不从展示说明中解析目标。
- 文件较多时按批次加载并提供“加载更多文件”，同时显示完整文件总数；加载动作不打开文件。历史超过当前查询上限也提供“加载更多提交”，不把截断结果显示为完整历史。
- 空仓库、没有匹配提交、空提交没有文件、读取失败分别显示对应文案。
- 选中行、展开状态和焦点通过标记与样式共同表达；拓扑连线贯穿展开文件区，文件行不绘制提交节点。
- 返回、收起、刷新及窗口缩放保留可定位的提交和滚动位置。引用移动后按完整 OID 保留选择；原目标不在新范围时清除选择，不能静默选中另一提交。

## 实施与验收边界

复用现有 Git 查询、结构化 Graph 模型、预览所有权、临时标签固定、Diff 与异步过期结果处理。新增提交文件与元数据的结构化读取，避免用显示文本反向识别提交。保持唯一终端及输入循环，不引入独立插件生命周期。

实施后验证以下可观察行为：

1. Changes 下仅有一个 Graph 历史列表，没有独立 Commits 区块；工具栏按钮打开或聚焦独立 Git Graph 大图，关闭后侧栏状态仍保留。全部引用与当前分支范围可区分，未合并分支仍可通过全部引用访问。
2. 单击任意可见提交，展开的是该行文件，右侧显示相同 OID 的完整说明；点击拓扑连线不打开提交。
3. 点击文件看到所选父提交到该提交的实际 Diff；返回后恢复提交、展开状态和阅读位置。
4. 快速切换提交、文件和仓库，延迟响应不串目标；固定标签不被后续临时选择覆盖。
5. 覆盖合并、首次提交、重命名、删除、二进制、空提交、大量文件及窄窗口；鼠标和键盘都能完成浏览。
6. 从工作区变更查看 Diff，再查看历史 Diff，确认目标与状态隔离；历史浏览不修改 HEAD、暂存区或工作区。
7. 大图单击提交显示下方详情，点击文件可查看 Diff 并返回；窄矮窗口仍有可达的返回入口，侧栏与大图不会互相抢占选择或滚动位置。

本稿记录设计及落地行为，实际执行的检查和平台限制见验证记录。Linux/Windows 原生交互不以本机测试结果替代。
