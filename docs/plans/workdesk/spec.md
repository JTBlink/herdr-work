# 复用优先工作台首版规格

主二进制为 `herdr-work`（Windows 为 `herdr-work.exe`）；产品及 crate 名称保持 Workdesk/workdesk。

本规格由当前讨论和固定版本源码整理，用户已确认按 13 项发布至 GitHub Issues；目录遵循四个自有 crate 与 upstream 原结构布局。父规格：[#1](https://github.com/JTBlink/herdr-work/issues/1)。技术设计见[复用优先架构](../../architecture/workdesk-architecture.md)，术语见[领域词汇](../../../GLOSSARY.md)，任务见[拆分草案](README.md)。

## Problem Statement

用户在 Herdr 中使用任务看板、文件/Git 和代码审查时，需要反复判断当前任务对应哪个 Agent 与 worktree，切换工具并重新定位代码。独立插件的界面状态和宿主识别各自管理，容易丢失上下文。

现有三个开源项目已经实现大量相关能力。工作台需要在保留这些实现的基础上提供连续操作，并正确处理多次执行、代码变化、后台推进和反馈目标。

## Solution


先交付已有任务到评论回填的完整路径，再扩展文件/Git 写操作、任务发起、后台恢复、旧数据导入和可安装发行物。首次用户路径为只读接入，写入动作必须明确选择目标并通过前置条件检查。

## User Stories

1. 作为使用者，我希望看到原有任务与候选尝试，以便继续已有工作。
2. 作为使用者，我希望区分任务、执行实例和 Agent 状态，以便知道当前进展及执行者。
3. 作为使用者，我希望选择明确的一次执行，以便查看它实际使用的 worktree。
4. 作为使用者，我希望定位执行 Agent 并返回工作台，以便继续对话和审查。
5. 作为使用者，我希望在两个任务间切换时保留选择和草稿，以便不中断工作。
6. 作为使用者，我希望查看指定执行的 staged/unstaged 与基线 Diff，以便理解改动。
7. 作为使用者，我希望对新增和删除侧的行范围写评论，以便准确反馈。
8. 作为使用者，我希望重启后恢复未发送评论，并看到代码变动提示，以便确认评论仍适用。
9. 作为使用者，我希望评论发回所选执行的 Agent，以便不会因焦点改变而发错人。
10. 作为使用者，我希望知道审查文本是已回填、明确失败还是结果未知，以便决定是否重试。
11. 作为使用者，我希望发送时新增或修改的评论仍保留，以便不丢失后续意见。
12. 作为使用者，我希望浏览文件并保持 SCM 与审查选择一致，以便减少重复定位。
13. 作为使用者，我希望正确查看重命名和嵌套仓库，以便操作实际所属仓库。
14. 作为使用者，我希望暂存、取消暂存和提交明确选中的内容，以便保留对 Git 写入的控制。
15. 作为使用者，我希望从工作台委派和停止任务，以便继续使用 Projects 的执行流程。
16. 作为使用者，我希望关闭 UI 后后台按既定策略运行，以便不影响已有 Agent。
17. 作为使用者，我希望断线和 pane 移动后恢复关联，身份无法确定时暂停发送，以便避免误操作。
18. 作为使用者，我希望旧数据导入前可预览并备份，以便能够恢复原工作方式。
19. 作为使用者，我希望重复打开工作台时返回已有实例，以便避免并行写草稿。
20. 作为使用者，我希望窄终端仍能完成相同工作，以便在 Agent pane 并排时使用。
21. 作为维护者，我希望知道导入版本、本地补丁和上游测试结果，以便升级时核对兼容性。
22. 作为使用者，我希望安装、升级和停用都明确管理工作台自己的进程，以便不影响其他插件或 Agent。

## Implementation Decisions

- 用户已确定复用三个来源项目的业务源码逻辑，并在 GitHub Issues 跟踪任务。本规格及 13 项任务已获用户确认，具体构建和运行能力仍需实施验证。
- 复用必须体现为原实现被编译和实际调用，以及相应上游行为测试被保留；任务侧 CLI 是进程边界，不代替源码接入。不得重新实现任务状态推进、Git 解析或 Diff/评论算法再仅保留原项目名称。
- 单 TUI 管理终端、布局、输入、焦点和弹层；上游 state、reducer 和渲染逐步适配，原运行循环不并行启动。
- Projects 独立后端保留 CLI、内部命令、任务格式和 keeper。新增有限命令及只读快照；不另建调度器或重写任务状态机。
- 任务权威记录由 Projects 维护；工作台执行关联由后端适配模块维护；Review 模块维护草稿与发送批次。
- 用户确认目录为 crates 下 workdesk-core、workdesk-engine、workdesk-tui、workdesk 四个自有 crate；来源代码进入 upstream 并保留原仓库结构、package/lib 名称、版本和锁文件。根 workspace 只管理自有成员，经统一入口编排工作台与 Projects 后端构建，不扁平化来源，不顺带重写逻辑。
- 新代码按 core、engine、tui 和入口划分；上游以业务模块为单位复用并维护版本化补丁。是否进一步拆 crate 由实际依赖决定。
- Execution 不与 attempt/run 简单一一对应；多个候选必须显式选择。身份不足、目录重建或绑定冲突时暂停自动发送。
- 视图读取按 epoch、generation 和请求输入判定有效性；业务操作按固定身份记录结果，切视图不丢失业务完成。
- 评论锚定读取快照；代码变化后标记过期。发送绑定固定批次和版本，成功只消费原批次中未被修改的评论。
- 回填请求采用明确成功、明确失败、结果未知三种结果；未知结果不自动重试，不承诺宿主不具备的幂等能力。
- Git 写入检查目标和预期状态、按作用范围协调，不能阻止外部 Git，因此检测到竞争要重新读取并报告。
- 工作台数据隔离，已有插件不与其共写。迁移提供预览、备份和可核对的导入映射；不在普通启动时改旧插件配置。
- 保留上游许可并由工作台统一发行版本和更新；平台、工具链和宿主保证以实际验收结果为准。

## Testing Decisions

测试以模块对使用者承诺的可观察行为为准。任务命令、执行关联、审查发送和 Git 操作通过 Engine 的领域接口验证；底层源码保持相应上游测试与 fixture，不以薄转发单测证明兼容性。

- 构建基线验证三个固定版本与新宿主的依赖解析、嵌入绘制、后端内部命令和许可来源。
- 任务到 Agent 路径验证两个任务、多个候选、pane 移动/重建及无副作用快照。
- Diff/Files 路径验证显式 worktree、嵌套仓库、rename、staged/unstaged、旧请求和刷新合并。
- 评论路径验证原锚点、过期提醒、重启恢复、模态输入与窄屏。
- 发送路径验证错误目标拒绝、回执丢失、发送期间编辑、成功后聚焦失败、崩溃恢复。
- Git 路径验证外部修改、锁冲突、切任务后完成、hook 失败和超时不重复提交。
- 后台路径验证重复 hook 不重复委派、UI 关闭后策略、停止调度与停止 Agent 的区别、后端路径和内部子命令。
- 迁移/发行路径验证隔离配置、导入中断、幂等重跑、原插件回滚，以及 macOS/Linux 各自安装和生命周期。

每个任务包含相关行为的验证，故障场景不推迟到最后统一补测。后续集成任务增加跨进程故障注入和恢复演示。

## Out of Scope

- 重写 Projects 任务状态机、引入第二套任务数据库或新的通用调度守护进程。
- 首版提供跨机器编排、Projects Web UI、全部自动化配置界面、forge PR 工作流。
- 在工作台内嵌 Agent PTY，或修改 Herdr 原生 GUI。
- Windows 完整工作台支持。
- 对三个原插件全部功能和快捷键承诺兼容。
- 未经确认修改现有插件注册、旧数据、运行 Agent 或发布软件 Release。

## Further Notes

当前已下载固定源码并重新检查关键实现；未构建上游、实现应用或执行真实 Herdr 验收。工具链和终端局部绘制仍是第一项任务的验证门槛。

已确认的默认配置见[工程流程配置记录](engineering-setup.md)。规格与各子任务 GitHub URL 已记入任务索引，并已核验原生 blocking/sub-issue 关系。此规格为发布快照，后续变更以 GitHub 父规格及相关任务为准。
