# HerdrWork 复用优先架构

2026-11-01 更新：产品集中于文件、Git、Diff 与审查。工程结构和依赖以[内部模块架构](herdr-work-internal-modules.md)为准；任务管理与后台编排已按 [ADR-0003](../adr/0003-remove-task-backend.md) 移除。

## 源码与运行结构

主程序 `herdr-work` 通过 Engine 执行业务用例，TUI 唯一拥有终端与输入。文件、搜索、编辑、Git 和预览复用迁入 `herdr-work-code` 的 Sidebar 实现，来源基线为 `081ed133f3faa377438b51ce435fe8a87c439593`，见[来源映射](../upstream/source-map.md)。运行进程与宿主连接由产品内部实现提供，见 [ADR-0002](../adr/0002-internal-runtime.md)。

## 工作上下文

执行身份关联实际工作目录实例和可选 Agent 目标。异步读取以 epoch、请求号及目录实例拒绝旧结果；前台不拼接 shell 命令，也不在绘制中进行阻塞 I/O。Git 写操作保留仓库写锁，执行前核对实例、HEAD、index 及内容指纹；未知结果保存操作日志并显式核对。

## 审查会话与发送契约


Agent 改动文件后，旧评论保留原锚点，标记 stale。重新定位评论需要用户确认；首版 stale 评论不允许自动发送，用户可刷新并重新确认锚点。切换工作目录或关闭 UI 后按 Review 身份恢复草稿，不按当前文件路径重新归属。

发送流程：

1. 固定待发送的 comment IDs/versions、文本快照、Execution 和目标身份，生成 BatchId。发送期间新增或编辑的评论不进入该批次。
2. 先持久化 prepared，再核对宿主当前 terminal/Agent、执行绑定和 worktree。发送调用前持久化 sending；不满足前置条件就停止。
3. 确认回执后持久化 delivered，只消费该批次中版本未被修改的评论；聚焦失败只显示警告。明确未送达则保留草稿并允许重试。
4. 可能已送达但无回执，或进程在 sending 后崩溃，恢复为 unknown；保留批次与草稿并阻止自动重发。先由用户核对目标输入/会话，确认未送达后才允许显式重试。

批次 ID 可用于工作台本地去重，不假定 Herdr 提供服务端幂等，也不承诺 exactly-once。重新核对和真正发送之间仍有竞态；只有宿主支持目标实例校验时才能原子消除，否则检测到不稳定绑定时拒绝发送，并保留该限制的验收记录。



## 界面与持久化

默认使用 Sidebar 的文件、搜索与 Git 活动；完整工作台额外提供审查。工作区选择、固定文档、搜索条件与提交草稿按目录实例保存，异步恢复不得覆盖当前输入或未保存编辑。数据目录固定为当前产品资料根，不读写独立插件的默认目录。

构建、安装与发行验证见[验收说明](../verification.md)。完整参考源码不参与生产构建，长期定制以本项目提交追踪。
